# i18n — SDK localization plus Tolgee

Issue [#6](https://github.com/paulthvt/folo-mlm/issues/6). Design decided
2026-09-24. Branches off `feature/24-motion-system`, because every string worth
keying lives there and not on `main`.

Two things ship together: the localization layer inside the app, and the
pipeline that fills the translated files without a human copying text between
tools.

---

## 1. Scope

In:

- `flutter_localizations` + `intl` + the SDK's `gen-l10n`. No third-party
  localization package.
- English source of truth in `lib/l10n/app_en.arb`, French as the first target.
- Every user-facing string in `lib/features/` and `lib/core/ui/` keyed.
- Domain stops returning English sentences.
- Tolgee Cloud free tier as the editor and machine translator.
- Two GitHub workflows: push English up, open a pull request with whatever came
  back translated.

Out, and why:

- **In-app language picker** — the device locale decides. A picker needs a
  settings screen, a persisted preference and a provider; none of that exists,
  and nothing asks for it yet.
- **RTL** — no RTL locale is planned. Flutter handles direction on its own when
  one arrives; the audit for hard-coded `left`/`right` padding is a separate job.
- **Localized dates, numbers, currencies** — the Today screen carries
  pre-formatted strings from sample data (§5). Real `intl` formatting arrives
  with the repository that produces real data.
- **Translating preview files and sample data** — see §5.
- **A CI job that creates Tolgee languages** — adding a language is a click
  (§8).

## 2. The localization layer

`pubspec.yaml` gains two SDK-adjacent dependencies and no third-party package:

```yaml
dependencies:
  flutter_localizations:
    sdk: flutter
  # ICU message formatting for the generated l10n class. Version is whatever
  # flutter_localizations pins — do not float it independently.
  intl: any
```

`l10n.yaml` at the repository root:

```yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart
nullable-getter: false
untranslated-messages-file: l10n_missing.json
```

`nullable-getter: false` so `AppLocalizations.of(context)` is non-nullable and
call sites carry no `!`.

**Generated Dart is not committed.** `flutter run` and `flutter build`
regenerate it, and `flutter gen-l10n` does so on demand; CI runs that step
explicitly before `analyze` and `test` rather than relying on which command
happens to trigger it.
Committing them instead would put a megabyte of generated diff in front of every
copy change. `.gitignore` gains:

```
lib/l10n/app_localizations*.dart
l10n_missing.json
```

`lib/app/app.dart` wires the delegates and drops its hard-coded title:

```dart
MaterialApp.router(
  onGenerateTitle: (context) => AppLocalizations.of(context).appTitle,
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  // ...
)
```

`supportedLocales` is generated from the ARB files present, so a new locale
needs no edit here — ever. That is the whole reason a pulled file is enough to
add a language.

Widgets read `AppLocalizations.of(context)`, conventionally into a local
`final l10n = AppLocalizations.of(context);` at the top of `build`.

## 3. Keys and ARB conventions

- Flat, `camelCase`, feature-prefixed: `authWelcomeTagline`,
  `todaySectionPriority`, `authEmailRequired`. No namespaces — Tolgee
  namespaces stay off, so the flat ARB maps one-to-one to keys.
- **Every key carries a `description`.** This is not documentation hygiene: the
  push step sends descriptions to Tolgee as key context, and the machine
  translator reads that context. A key without a description gets translated
  blind. This is the one convention that visibly degrades output when skipped.
- Interpolation uses ICU placeholders with declared types, never Dart string
  interpolation of a translated fragment. `check_inbox_page.dart` currently
  builds `'We sent a confirmation link to ${widget.email}...'`; that becomes a
  placeholder.
- Numbers that appear in copy come through as placeholders, so the sentence
  stays one translatable unit. `'At least 8 characters'` and
  `minPasswordLength` must not drift apart.

```json
{
  "@@locale": "en",
  "authPasswordTooShort": "At least {count} characters.",
  "@authPasswordTooShort": {
    "description": "Validation error under the password field when it is shorter than the minimum.",
    "placeholders": { "count": { "type": "int" } }
  },
  "authCheckInboxBodyWithEmail": "We sent a confirmation link to {email}. Open it to finish setting up your account.",
  "@authCheckInboxBodyWithEmail": {
    "description": "Body of the check-your-inbox screen after registration, when the address is known.",
    "placeholders": { "email": { "type": "String" } }
  }
}
```

- Plurals use ICU `plural`, not a hand-rolled `count == 1 ? ... : ...`. Nothing
  in the current copy needs one; the rule exists so the first one does not
  invent its own shape.

## 4. What gets keyed

Keyed — roughly 70 strings:

| Area | Examples |
| --- | --- |
| `features/auth/presentation/` (6 pages + 3 widgets) | "Create your account", "Continue with Google", "Resend email", "Back to sign in" |
| `features/auth/presentation/auth_failure_copy.dart` | the 7 failure sentences |
| validation copy, relocated out of `domain` (§5) | "Enter your email address.", "Those passwords do not match." |
| `features/today/presentation/today_page.dart` | "Today", "Priority", "This month", "You talked to", the empty state |
| `core/ui/action_item.dart` | "Mark as done" — the only literal in `core/ui` |
| `app/app.dart` | `appTitle` |

Deliberately left in English:

- **`*_preview.dart`** (`ui_preview`, `theme_preview`, `today_preview`) — 67 of
  the 157 matched literals live here. These are developer tools that never ship
  to a user. Translating them costs hosted words and buys nothing.
- **`sampleToday` in `today_snapshot.dart`** — fictional contacts and
  pre-formatted sentences used by previews and widget tests. It is fake content,
  not interface copy. The screen's chrome around it is keyed; the fake data is
  not. See §10.
- **"Folo"** — a product name.
- **`assets/images/google_g.png`** and other asset paths, route paths, Supabase
  error codes, `'confirm'` / `'reset'` route parameters.

## 5. Domain stops carrying copy

`features/auth/domain/auth_validation.dart` returns English sentences today, so
`domain` would need a `BuildContext` to be localized — which the layering rule
forbids. The validators return a problem instead, and `presentation` maps it:

```dart
// domain/auth_validation.dart
enum EmailProblem { empty, malformed }
enum PasswordProblem { empty, tooShort }
enum FirstNameProblem { empty }
enum PasswordConfirmationProblem { empty, mismatch }

EmailProblem? validateEmail(String? value) { /* ... */ }
```

```dart
// presentation/auth_validation_copy.dart
String? emailFieldError(AppLocalizations l10n, String? value) =>
    switch (validateEmail(value)) {
      null => null,
      EmailProblem.empty => l10n.authEmailRequired,
      EmailProblem.malformed => l10n.authEmailInvalid,
    };
```

Pages pass `validator: (value) => emailFieldError(l10n, value)`. Exhaustive
`switch` over the enum means a new problem is a compile error at every call
site, which a nullable `String` never gave us.

`auth_failure_copy.dart` keeps its shape and gains an `AppLocalizations`
parameter:
`String authFailureCopy(AppLocalizations l10n, AuthFailure failure)`.

Existing domain tests compare enums instead of sentences — a strictly better
test, since copy edits stop breaking domain tests.

## 6. Tolgee setup

Manual, once, outside the repository:

1. Tolgee Cloud project, free tier. Base language `en`, target `fr`.
2. Project settings → **Machine translation**: enable auto-translation of new
   keys. This is what fills a new key in every target language at import time,
   so no CI step calls a translate endpoint.
3. Project API key (PAK, not a personal access token) with
   `keys.view`, `keys.edit`, `translations.view`, `translations.edit`,
   `translations.state-edit`, `import`. Stored as the repository secret
   `TOLGEE_API_KEY`. A PAK carries its project id, so no `--project-id` flag is
   needed.

Ownership, stated once because both workflows depend on it:

- **The repository owns which keys exist and what English says.** Never edit
  English in the Tolgee UI; the next push overwrites it.
- **Tolgee owns every non-English translation.** Never hand-edit `app_fr.arb`;
  the next pull overwrites it.

The free tier bills hosted words as `words × target languages`, capped at
30 000. Keeping previews and sample data out of the ARB (§4) is what keeps the
whole app comfortably inside that.

## 7. The two workflows

`.github/workflows/l10n-push.yaml` — on `push` to `main`, filtered to
`lib/l10n/app_en.arb`:

```yaml
- run: npx --yes @tolgee/cli@2 push
        --force-mode OVERRIDE
        --languages en
        --override-key-descriptions
        --remove-other-keys
  env:
    TOLGEE_API_KEY: ${{ secrets.TOLGEE_API_KEY }}
```

- `--languages en` — the push must not touch a translation.
- `--override-key-descriptions` — descriptions are the translator's context
  (§3).
- `--remove-other-keys` — an English key deleted in the repository is deleted in
  Tolgee. Without it, a removed key lives on in the platform and keeps coming
  back in every language's pull.

`.github/workflows/l10n-pull.yaml` — `workflow_dispatch` plus a weekly cron:

```yaml
- run: npx --yes @tolgee/cli@2 pull --path lib/l10n
  env:
    TOLGEE_API_KEY: ${{ secrets.TOLGEE_API_KEY }}
- uses: peter-evans/create-pull-request@v7
  with:
    branch: chore/l10n-sync
    title: "chore(l10n): sync translations"
    commit-message: "chore(l10n): sync translations"
    body: "Automated Tolgee pull. Review the copy, then merge."
```

- No `--languages` filter: one run exports every language, so one pull request
  carries all of them. One branch, reused — a second run updates the open pull
  request instead of opening another.
- No `--states` filter either, which is the default "everything except
  untranslated". Machine output reaches the pull request directly and the pull
  request is the review gate. The alternative, `--states REVIEWED`, is honest
  for French and theatre for a language nobody on the project reads, while
  silently keeping strings out of the app.
- No `--empty-dir`: it would delete the generated Dart sitting in the same
  folder.
- `create-pull-request` is a no-op when nothing changed, so the cron is quiet by
  default.
- Neither workflow runs on a fork pull request, so the secret is never exposed
  to one.

## 8. Adding a language

1. Add the language in the Tolgee UI. Auto-translation fills it from the
   existing keys.
2. Run the pull workflow.
3. Review and merge the pull request. It contains a new `lib/l10n/app_xx.arb`;
   `supportedLocales` picks it up with no code change.

No empty placeholder file is committed first — an ARB file in the repository
cannot create a language in Tolgee, and the pull creates the file itself.

## 9. Testing and quality gates

- **One new unit test**: every key in every non-`en` ARB exists in
  `app_en.arb`. A subset check, not equality — a lagging language is normal and
  `gen-l10n` falls back to English for a missing key, but a key that exists
  *only* in French means a rename went wrong.
- **Widget tests**: each test host gains
  `localizationsDelegates: AppLocalizations.localizationsDelegates` and
  `locale: const Locale('en')`. Assertions keep their English literals, so they
  double as copy locks.
- **CI**: `flutter gen-l10n` runs before `flutter analyze`, otherwise analysis
  fails on the missing generated file.
- `dart format .`, `flutter analyze` clean, `flutter test` green, as always.

## 10. Known debt this ships with

- **`TodaySnapshot` carries formatted English.** `greeting`, `dateLabel`,
  `progressLabel`, `effortLabel`, `goal.pace`, `goal.timeLeft` are sentences,
  not data. Fine while the only producer is `sampleToday`. When a real Today
  repository lands, those fields become data (`DateTime`, `int`, an enum) and
  the screen formats them with `AppLocalizations` and `intl`. Localizing it now
  would mean keying fake content.
- **English copy lives in two places for tests.** Widget tests assert literals
  that also live in `app_en.arb`. Accepted: the duplication is what catches an
  accidental copy change.
- **`intl: any`.** Pinned in practice by `flutter_localizations`. If a resolve
  conflict ever appears, pin it then, not now.
- **The pull is manual or weekly, not per-merge.** A string added today is
  English-only until the next pull. `gen-l10n`'s fallback makes that a
  cosmetic lag, not a crash.
